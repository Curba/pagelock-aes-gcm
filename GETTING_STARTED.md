# Getting started

This guide takes you from a fresh checkout to a passing regression and shows
how to pick a configuration. Everything runs from the `aes_gcm_ip/` root.

## 1. Prerequisites

| Tool | Tested version | Used for |
|---|---|---|
| Verilator | 5.052 | SystemVerilog benches, default cocotb simulator, lint |
| Icarus Verilog | 13.0 | Optional second cocotb simulator, elaboration checks |
| Verible (`verible-verilog-lint`) | any recent | Style lint (`make lint`) |
| Bender | any recent | Generates the Verilator file list from `Bender.yml` |
| Python | 3.12+ | cocotb 2.0, `cryptography`, `pycryptodomex`, `pytest` |
| Surfer (optional) | any | `make wave` |

Only Verilator, Bender and Python are strictly required. If Bender is not
available, `rtl/filelist.f` is an equivalent plain file list for the RTL.

## 2. Python environment

```
make venv
source .venv/bin/activate
```

This creates `.venv` and installs `cocotb>=2.0`, `cryptography>=42`,
`pycryptodomex>=3.20` and `pytest>=8` (the same list is in the README). The
cocotb Makefile needs `cocotb-config` on `PATH`, so activate the environment
in every shell you use for `make cocotb*` or `make matrix`.

## 3. Sanity checks (about one minute)

```
make lint            # Verible style lint + Verilator -Wall for KEY_W=128 and 256
make elab-check      # 20 legal/illegal parameter sets on Verilator and Icarus
make conformance     # Python reference vs NIST CAVP (128 + 256) and McGrew-Viega
make cocotb-kat      # cocotb KAT, AES-128, 256-byte page, Verilator
```

Expected: lint clean, `elab-check: 40/40 expectations met`,
`1508 PASSED, 0 FAILED`, `TESTS=3 PASS=3 FAIL=0`.

## 4. Full regression

```
make sim-all         # 13 SystemVerilog benches (default configuration + tb_aes_gcm_param)
make matrix          # documented cocotb matrix over key size, page size and suite
```

`make sim-all` prints one `[PASS]`/`[FAIL]` line per bench and a summary.
`make matrix` prints one line per (KEY_W, PAGE_BYTES, suite) with the log
path on failure; logs go to `build/matrix_*.log`, reports to
`build/reports/`. The README's Verification section lists what each suite
covers and the last recorded results.

## 5. Choosing a configuration

The two knobs are `KEY_W` (128 or 256) and `PAGE_BYTES` (multiple of 16, at
least 48). The payload per command is `PAGE_BYTES - 32` bytes.

Run any cocotb suite on any configuration:

```
make cocotb KEY_W=256 PAGE_BYTES=4096 MODULE=test_aes_gcm_random
make cocotb KEY_W=128 PAGE_BYTES=48   MODULE=test_aes_gcm_geometry SIM=icarus
AES_RANDOM_COUNT=512 AES_RANDOM_SEED=0xDEADBEEF make cocotb KEY_W=256 MODULE=test_aes_gcm_random
```

Waveforms for a cocotb run: add `WAVES=1` (Verilator, FST under
`build/cocotb/verilator/<config>/sim_build/`). For an SV bench:
`make sim TB=tb_aes_gcm_top` then `make wave TB=tb_aes_gcm_top`.

Try an illegal configuration to see the guard:

```
verilator --lint-only --top-module aes_gcm_top -GPAGE_BYTES=100 -f rtl/filelist.f
# %Warning-USERFATAL: rtl/aes_gcm_top.sv: aes_gcm_top: PAGE_BYTES must be a multiple of 16
```

## 6. Instantiating the block

```systemverilog
aes_gcm_top #(
  .KEY_W      (256),
  .PAGE_BYTES (256)
) u_aes_gcm (
  .clk_i, .rst_ni,
  .cmd_valid_i, .cmd_ready_o, .cmd_mode_i, .cmd_key_i, .cmd_iv_i, .cmd_aad_i, .cmd_exp_tag_i,
  .data_in_valid_i, .data_in_ready_o, .data_in_i,
  .data_out_o, .data_out_valid_o, .data_out_ready_i, .data_out_last_o,
  .rsp_valid_o, .rsp_ready_i, .rsp_auth_ok_o, .rsp_error_o
);
```

Compile order (also in `Bender.yml` and `rtl/filelist.f`):
`aes_gcm_pkg.sv`, the six Secworks `.v` files, `aes_ghash.sv`,
`aes_gcm_fsm.sv`, `aes_gcm_oc.sv`, `aes_gcm_top.sv`.

Driving it: see the operation sequences in `docs/interface.md`. The cocotb
driver `tb/cocotb/aes_gcm_driver.py` is a complete, protocol-checking
reference implementation of a producer and consumer.

## 7. Where things are

```
rtl/                 RTL (pkg/, the four block modules, filelist.f, waiver)
rtl/third_party/     Secworks AES core (read-only, BSD licence)
tb/sv/               SystemVerilog benches (unit/, output/, integration/)
tb/cocotb/           cocotb driver and suites (kat, negative, random, geometry)
tb/conformance/      NIST CAVP sweep of the Python reference + vectors
tb/elab/             elaboration guard regression
tb/vectors/          golden .hex vectors (generated by scripts/gen_gcm_vectors.py)
docs/                architecture, interface, parameters, page format, verification, decisions
build/               all generated output (ignored by git)
```
