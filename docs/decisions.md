# Decisions log

Decisions taken while turning the fixed AES-128 / 256-byte `sec_cipher` block
into the standalone parameterised `aes_gcm_ip`. Items marked *(agreed)* were
settled with the block owner before implementation; the rest were taken
during implementation and are recorded here so they can be revisited.

| # | Decision | Rationale |
|---|---|---|
| 1 | *(agreed)* New self-contained folder `aes_gcm_ip/` with its own RTL, benches, docs, Makefile and Bender manifest; `sec_cipher` untouched and unrelated. | Standalone deliverable. |
| 2 | *(agreed)* Module names unchanged (`aes_gcm_top`, `aes_gcm_fsm`, `aes_gcm_oc`, `aes_ghash`, `aes_gcm_pkg`). | Existing benches and integrators keep working. The two projects are never compiled together. |
| 3 | *(agreed)* `KEY_W` is an elaboration parameter, one key size per instance, not a runtime select. | Matches the request; avoids a 256-bit port on AES-128 builds. |
| 4 | *(agreed)* Page size is the elaboration parameter `PAGE_BYTES`, checked at compile time. There is no runtime page-size port. | Compile-time checking of illegal values is only possible for parameters. |
| 5 | *(agreed)* AAD stays one 128-bit block for both key sizes; the page trailer is 32 bytes in every configuration. | Keeps the page format and the output controller identical across key sizes. |
| 6 | IV fixed at 96 bits (`IV_W` parameter exists but must be 96). | Other IV lengths need a GHASH-derived J0 and a different FSM entry sequence; the owner allowed keeping the current construction. |
| 7 | Tag fixed at 128 bits. | GCM's tag is 128 bits regardless of key size; truncation is a policy choice left to the integrator. |
| 8 | Same watchdog default (4095) for both key sizes, produced by `gcm_wdt_timeout_default()` in the package. | Measured: AES-256 only adds 4 cycles to the setup phase. A single function is the place to change if a project wants otherwise. |
| 9 | Elaboration guards are generate-scope `$fatal` with single-string messages. | Portable across Verilator, Icarus and synthesis; Icarus does not accept format arguments in elaboration tasks. |
| 10 | The Secworks AES core is copied (not a submodule) with its BSD licence and README, and treated as read-only. | Self-contained checkout with no network dependency. |
| 11 | The `sec_module_pkg` dependency is removed; benches carry explicit localparams for the default geometry. | A package of fixed widths is misleading in a parameterised IP. |
| 12 | cocotb suites derive all geometry from environment variables set by the Makefile from the same `KEY_W` / `PAGE_BYTES` / `WDT_TIMEOUT` given to the simulator. | One source of truth per run; the original KAT / negative / random suites scale without per-configuration copies. |
| 13 | Verilator is the default cocotb simulator; Icarus remains selectable (`SIM=icarus`). | Verilator is 10x faster on the large-page runs; Icarus keeps the original flow available. |
| 14 | `tb_oc_ready_skew.sv` is not carried over. | It encodes the v1 completion semantics (`page_done` aligned with the AAD beat) and fails identically on the original `sec_cipher` RTL; it was never part of the original `sim-all` list. Its scenarios (ready skew and stalls on the tag and AAD beats) are covered by `tb_aes_gcm_backpressure` (STALL_ON_TAG / STALL_ON_AAD), `tb_v2_contract` and the cocotb ready patterns. |
| 15 | RTL fix in `aes_gcm_oc`: `cmd_accept_i` now takes priority over `err_i` in the state register. | The FSM error flag is sticky and clears on the same edge that accepts the next command. In the original ordering that command left the output controller parked in `OC_IDLE`, so its output was never streamed and the operation hung. Found by the new `test_watchdog_threshold`, which recovers without a reset; the original negative suite always reset after a watchdog scenario and therefore never reached this path. The original `sec_cipher` RTL has the same latent issue. |
| 16 | New golden vectors for the SV parameter bench are generated by `scripts/gen_gcm_vectors.py --all`; the legacy `ct.hex` / `tag.hex` remain byte-identical to the originals. | Existing benches stay comparable with the original repository. |
| 17 | NIST CAVP 256-bit response files were fetched from NIST and added next to the 128-bit ones; the conformance sweep now covers both key sizes plus McGrew-Viega TC13-TC16. | The Python reference used by every bench is validated for every supported key size. |
| 18 | Beat counts are enforced structurally: `data_in_ready_o` is never asserted after the `NBLOCKS`-th beat. Extra offered input is ignored, missing input is a watchdog error. | Same behaviour as the original; now regression-tested per configuration (`test_block_counts`). |
| 19 | The informational `ENC_OUT_BLOCKS` / `DEC_OUT_BLOCKS` localparams are kept even though the RTL does not use them. | Integrators and benches can read the expected beat counts from the instance. |
